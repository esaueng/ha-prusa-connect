`deviceapi` is how a module reads the fleet and drives one device from inside
the host. `List` and `Get` answer devices; `Command` sends one verb and
answers what the machine made of it; `Approve` admits a device waiting on a
registration code. The calls travel over the session the host already holds
with the module, so a module needs no address and no credential.

Every params object carries a `Principal`, and it is the field `routes.serve`
handed in. A module serving a person passes that person back out. The host
checks it is one it handed this module in a request still being served, and
the graph answers for that person. An empty principal is the module's own
work, resolved against the instance's own grants. So a module sees what the
caller would see at the HTTP API and cannot widen it. A principal the host
never handed this module is `ErrDenied`.

A module builds one `Client` with `NewClient` over its `wirerpc.Conn`. A
device the module may not see and one the server never met are one answer,
`ErrNoDevice`, so a module cannot enumerate a fleet it was granted nothing on.

```go
package shelf

import (
	"context"
	"log"
	"slices"

	"github.com/prusa3d/prusa-connect/sdk/deviceapi"
)

const pause = "core.command.pause_print"

// pauseLab pauses every connected printer in the lab that the caller may
// operate. principal is who routes.serve handed the module, passed back out.
func pauseLab(ctx context.Context, fleet *deviceapi.Client, principal string) error {
	page, err := fleet.List(ctx, deviceapi.ListParams{
		Principal: principal,
		Labels:    []string{"room=lab"},
	})
	if err != nil {
		return err
	}

	for _, device := range page.Items {
		if !device.Connected || !slices.Contains(device.Capabilities, pause) {
			continue
		}

		result, err := fleet.Command(ctx, deviceapi.CommandParams{
			Principal: principal,
			ID:        device.ID,
			Verb:      pause,
		})
		if err != nil {
			return err
		}

		// A refusal is a result and not an error: the printer answered.
		if !result.OK {
			log.Printf("%s refused: %s", device.ID, result.MachineReason)
		}
	}

	return nil
}
```

A `Limit` above `MaxPageLimit`, 200, is refused rather than clamped. A
device's `CapabilityEpoch` moves whenever it reconnects, so a set cached under
an older epoch describes a device that is gone. `Approve` takes `admit_device`
on the driver resource kind, which reading the fleet does not carry.

### Objects a print skipped

A slicer can label each object on the bed, and a machine can then skip one
object and finish the rest. A `Job` from `Jobs` or `JobHistory` carries those
objects when the machine reports them. `ObjectCount` is how many objects the
machine reported, and `Objects` lists them by id, each with `Cancelled`. Both
fields are absent for a machine that said nothing about objects. A count of 0
is a print with no labelled objects.

A finished print keeps the last set the machine reported before the end. So
`Jobs(...).Last` and every row of `JobHistory` answer how many objects the
print had and which of them it skipped:

```go
func skipped(job deviceapi.Job) (total int, cancelled []int, known bool) {
	if job.ObjectCount == nil {
		return 0, nil, false
	}

	for _, object := range job.Objects {
		if object.Cancelled {
			cancelled = append(cancelled, object.ID)
		}
	}

	return *job.ObjectCount, cancelled, true
}
```

`Objects` holds at most `MaxJobObjects`, 256, and a name holds at most
`MaxJobObjectNameBytes`, 64 bytes. A print with more objects keeps every
cancelled object first. A client refuses a job over either bound. Prusa
printers on Buddy firmware report the ids and the flags, and no names.

Package deviceapi is how a module reads the fleet and drives one device.

It is the fourth door in the same wall as sdk/routesapi, sdk/stateapi and sdk/busapi, and it is the first that travels inward: a request arrives through routes.serve, a record travels out through state.put, a fact travels out through bus.emit, and a reading comes back through the methods here.

### Who a call is made as

Every params object carries a Principal, and it is the same field routes.serve hands a module on the way in. A module serving a person's request passes that person's principal back out, the host checks it is one it handed this module in a request still being served, and the authorization graph answers for that person before the module sees a row. A principal the host never handed this module is ErrDenied.

A call with no principal is the module's own work: a sync loop, a poll, anything with no person behind it. The host resolves it against the instance's own principal, which is \`sink:\<instance>\` under an earlier design decision, so a module that was granted nothing lists nothing and no module can widen what an operator gave its instance.

That is the same rule the HTTP surface serves callers under. One population is resolved one way, and a module reading a fleet sees what the caller would see at the API.

### Why this is not an HTTP call

A module is a child process the host launched, and the session it already holds is authenticated by construction: the host verified the artefact's digest before it executed anything. Reaching back over HTTP would need an address the child does not have and a credential this project does not mint, to ask a question the open pipe can already carry.
